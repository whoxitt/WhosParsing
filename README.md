# Telegram Collectible Gifts Parser — Bothost Python package

Версия конфигурации: PostgreSQL без Redis, несколько Telethon-аккаунтов, TonAPI от TON Console. Запуск как обычного Python-проекта на Bothost, без Docker.

## Что заполнить

В `.env` или в Environment Variables Bothost заполните только: `BOT_TOKEN`, `ADMIN_IDS`, `REQUIRED_CHANNEL_ID`, `REQUIRED_CHANNEL_URL`, `DATABASE_URL`, `ACCOUNT_CREDENTIALS_SECRET`, `TON_WALLET_ADDRESS`, `TON_API_TOKEN`. `BOT_USERNAME` необязателен. Остальные значения имеют настройки по умолчанию. Не загружайте секретный `.env` в публичный репозиторий.

`DATABASE_URL` должен быть формата `postgresql+asyncpg://USER:PASSWORD@HOST:5432/DATABASE`. Если провайдер требует SSL, используйте выданный им формат подключения и убедитесь, что он совместим с asyncpg. База уже должна существовать; приложение создаёт таблицы через SQLAlchemy `create_all` при старте, но не создаёт сам сервер/базу. Для существующей базы с конфликтующими таблицами сначала сделайте резервную копию и согласуйте миграцию.

## Bothost

1. Создайте Python-приложение и загрузите содержимое архива.
2. Главный файл: `main.py`.
3. Установка зависимостей: `pip install -r requirements.txt` (или штатная установка Bothost).
4. Убедитесь, что Bothost предоставляет постоянное файловое хранилище для `/app/data` и `/app/backups`. Если путь иной, измените `TELETHON_SESSION_DIR` и `BACKUP_DIR`.
5. Вставьте обязательные переменные в панель Environment Variables.
6. Запустите один экземпляр приложения. Не запускайте несколько копий polling-бота с одним BOT_TOKEN.

## Redis

Redis не используется и не требуется. В проекте нет `REDIS_URL`; очереди/данные хранятся в PostgreSQL.

## TonAPI / TON Console

Используется `https://tonapi.io/v2` и заголовок `Authorization: Bearer <TON_API_TOKEN>`. Проверка настроена fail-closed: неизвестный формат ответа, отсутствующий комментарий, несовпадение memo/адреса/суммы или повторный tx hash не дают доступ. При неправильном/отсутствующем Memo доступ не выдаётся.

**Перед включением продаж обязательно провести тестовый платёж в контролируемой среде.** TonAPI меняет схемы и представление адресов; текущий обработчик требует точного совпадения destination с `TON_WALLET_ADDRESS`. Если API возвращает другой формат адреса, платёж останется неподтверждённым (это безопаснее ошибочного зачисления), и потребуется адаптация нормализации адресов. Проверяйте также фактическую структуру `in_msg` и decoded comment на реальном тестовом переводе. Не принимайте платежи до такого теста.

Memo генерируется уникальным для каждого счёта. Проверяются точная сумма, точный memo, получатель и уникальный hash транзакции. Платёж с неправильным memo не зачисляется. Поступившие средства при этом остаются в кошельке; бот не может их вернуть автоматически.

## Несколько Telethon-аккаунтов и API credentials

Для каждого Telethon-аккаунта администратор добавляет отдельно API ID и API Hash, затем номер телефона, код Telegram и при необходимости пароль 2FA через личный чат с ботом (`/admin` → «Добавить аккаунт»). API Hash хранится в PostgreSQL только в зашифрованном виде. Для шифрования обязательно задайте `ACCOUNT_CREDENTIALS_SECRET` в Environment Variables Bothost: длинную случайную строку (не менее 32 случайных символов). Её можно сгенерировать командой `python -c "import secrets; print(secrets.token_urlsafe(48))"`. Не меняйте этот секрет после добавления аккаунтов, иначе старые API Hash нельзя будет расшифровать и сессии не восстановятся. Входящие сообщения с API Hash, кодом и паролем бот пытается удалить после обработки; всё равно не отправляйте эти данные в групповые чаты.

Каждому аккаунту нужна отдельная `.session` в постоянном каталоге `TELETHON_SESSION_DIR`. Подключайте только аккаунты, которыми вы вправе управлять. Telegram может ограничивать частоту запросов; FloodWait нужно уважать, не пытаться обходить. Каждый аккаунт видит только доступные ему чаты. Скрытых участников или недоступные подарки нельзя гарантированно извлечь.

## Важные ограничения текущей сборки

Это обновлённый starter-проект, не сертифицированный production-релиз. Архив сохраняет ранее реализованные обработчики и менеджер аккаунтов, но перед коммерческим запуском необходимы интеграционные проверки: реальная авторизация нескольких аккаунтов и 2FA, управление чатами в админке, устойчивое распределение задач между аккаунтами, корректность NFT-метода на актуальном MTProto layer, trial/referral, а также TON тестовая транзакция. Не обещается гарантированно 10 профилей: результат зависит от доступности чатов/профилей и ограничений Telegram.

## Безопасность

- `.env` уже включён как шаблон с placeholder-значениями. Замените их своими секретами до запуска.
- Не отправляйте API HASH, BOT TOKEN, TON API TOKEN или Telethon `.session` третьим лицам.
- Ограничьте доступ к `/app/data/sessions`. Файл `.session` даёт доступ к Telegram-аккаунту.
- Настройте резервные копии PostgreSQL на стороне хостинга или через `pg_dump`; параметр BACKUP_* сам по себе не гарантирует резервирование базы.

## Диагностика коллекционных NFT

В панели администратора откройте «Чаты», выберите Telethon-аккаунт и нажмите «Проверить NFT у профиля». Отправьте публичный username (например, `@username`). Бот проверит профиль выбранным Telethon-аккаунтом через MTProto `payments.getSavedStarGifts` и покажет число возвращённых подарков, типы объектов и ссылки `https://t.me/nft/<slug>` для `StarGiftUnique`.

Для NFT-поиска используется Telethon 1.46.0 с обновлённым TL-слоем. Ошибки чтения подарков в парсере записываются в журнал как предупреждения и отдельно учитываются в статистике; ошибка запроса не считается достоверным отсутствием NFT.


## Исправление массовой выдачи NFT-профилей

В этой сборке исправлен путь от обнаружения `StarGiftUnique` до отправки результата пользователю:

- Ошибка отправки уведомления больше не маскируется под ошибку доступа к профилю.
- Найденный профиль закрепляется за пользователем, которому предназначена выдача. Если уведомление не доставилось, запись не освобождается и повторная отправка выполняется при следующем запуске парсера.
- Добавлено поле `owner_profiles.delivered_at`; оно добавляется автоматически при старте существующей PostgreSQL-базы.
- Ранее сохранённые, но не выданные записи `owner_profiles` можно подобрать и выдать, если они ещё не закреплены за другим пользователем.
- Если проверка одного аккаунта завершилась ошибкой, тот же Telegram-пользователь может быть повторно проверен другим подключённым аккаунтом.
- Итоговый отчёт показывает найденные username/ID и отдельно ошибки доставки уведомлений.
- Уведомление отправляется обычным текстом с NFT-ссылками, без потенциально проблемной inline-кнопки `tg://user?id=...`.

Изменены только `app/services/parser.py`, `app/db/models.py`, `app/db/session.py` и `main.py`. Платежи, пользователи, доступы, рефералы, аккаунты, чаты и функция очистки результатов парсинга не менялись.

После загрузки файлов выполните Rebuild/пересборку контейнера на хостинге. Проверьте журнал приложения по меткам `NFT_CHECK`, `NFT_DELIVERED`, `NFT_NOTIFICATION_PENDING` и `NFT_ACCESS_ERROR`.


### Красивое уведомление о найденном NFT-владельце

В `main.py` уведомление о найденном владельце оформлено HTML-карточкой: имя, Telegram ID, количество коллекционных NFT, кликабельные NFT-ссылки и чат-источник. Добавлена inline-кнопка «👤 Перейти в профиль». Если у пользователя есть username, кнопка открывает `https://t.me/<username>`; если username отсутствует, используется `tg://user?id=<id>`.


## Расширенная админ-панель

Команда `/admin` открывает управление аккаунтами Telethon, чатами, настройками парсера,
пользователями и платежами. Настройки лимитов сохраняются в таблице `bot_settings` и
переживают перезапуск контейнера:

- максимальное число NFT-профилей за поиск;
- лимит профилей пробного доступа;
- кулдаун пользователей (администраторы обходят его);
- длительность платного доступа;
- цена в TON (целое число TON через меню).

Команды администратора:
- `/grant TELEGRAM_ID ЧАСЫ` — выдать/продлить доступ;
- `/revoke TELEGRAM_ID` — отозвать платный доступ;
- `/admin` — открыть панель управления.

Бот отправляет администраторам из `ADMIN_IDS` уведомления о новых пользователях,
активации пробного доступа, подтверждённых платежах и завершении парсинга.
Для получения уведомлений администратор должен предварительно открыть личный чат с ботом
и нажать `/start` (ограничение Telegram на первые сообщения бота).
